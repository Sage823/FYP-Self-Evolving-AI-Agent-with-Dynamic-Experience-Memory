# 排查记录

## 问题

项目声明了依赖和测试，但当前电脑的系统 Python 与 Codex 捆绑 Python 均缺少运行所需的 pytest、SciPy 等包，无法直接执行校验和实验。验证过程中另发现精确 McNemar 检验的双侧 p 值被重复乘以二。

## 排查步骤

- [x] 检查系统 Python、捆绑 Python 和项目依赖声明
- [x] 创建项目本地 `.venv`
- [x] 验证 `ensurepip` 失败发生在受限临时目录，而非项目代码
- [x] 使用系统 pip 的 `--python .venv` 方式把依赖安装到隔离环境
- [x] 运行 benchmark 校验、单元测试和离线端到端流程
- [x] 为 McNemar p 值补充先失败的回归测试
- [x] 修复统计计算并重跑全部测试
- [x] 检查真实模型凭据是否存在，未读取或输出任何密钥

## 假设与验证

1. 假设：项目失败是源代码导入错误。验证：系统 Python 报 `ModuleNotFoundError: scipy`，依赖安装后同一路径可正常导入，说明首要根因是环境未配置。
2. 假设：虚拟环境无法使用。验证：`ensurepip` 因 Windows 隔离临时目录拒绝写入而失败；改用系统 pip 定向安装到 `.venv` 后，全部核心依赖可导入。
3. 假设：现有测试均能通过。验证：第一次运行有 4 项通过、1 项在 pytest 创建临时目录时出错；把 `--basetemp` 指向项目可写目录后，6 项全部通过。
4. 假设：统计实现正确。验证：构造 1 比 9 的不一致配对，预期双侧精确 p 值为 0.021484375，原实现返回 0.04296875，确认发生重复加倍。
5. 假设：可以执行真实模型实验。验证：未发现支持的环境变量或本地凭据文件，因此只执行离线完整流程，未伪造真实实验结果。

## 根因定位链

无法运行 → Python 缺少声明依赖 → 项目没有已配置的隔离环境 → 创建 `.venv` 时 `ensurepip` 又被受限临时目录阻止 → 改用系统 pip 定向安装后环境恢复。

统计偏差 → `binomtest` 默认已经返回双侧 p 值 → 代码再次乘以二 → p 值系统性偏大。

## 修复方案

项目已建立并配置 `.venv`；README 增加显式虚拟环境步骤。统计函数直接采用 SciPy 返回的双侧精确 p 值，并由新增回归测试锁定。最终 benchmark 校验通过、6 项测试通过、离线端到端实验成功完成。真实模型运行仍需用户提供项目支持的 API 凭据。
